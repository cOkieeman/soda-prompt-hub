# Soda Prompt Hub 用户操作与人工验收说明（草稿）

本文保留 1.1.1 的操作与验收记录。1.2.0 的下载和首次使用见[快速开始](QUICK_START.md)，新版创作台与画廊见[创作指南](CREATIVE_AI_GUIDE.md)。

本文按“从哪里进入、点什么、看到什么算正常”说明 1.1.1 预发布候选的主要操作。它同时可以作为发布前人工验收记录。界面名称以简体中文 WebUI 为准。

当前人工验收中发现的未修复问题见 [Windows 单机人工验收问题记录](acceptance/windows-standalone-issues-20260914.md)。遇到文中已记录的问题时不必反复操作，保留截图和任务编号即可。

## 1. 先确认自己使用哪种模式

| 模式 | 启动方式 | WebUI 和个人资料所在设备 | 负责出图的程序 |
| --- | --- | --- | --- |
| Windows 单机 | Windows 打开 `Soda Prompt Hub` | Windows | 启动器自动管理本机 Worker；不要再开独立 Worker |
| Mac 管理 Windows | Mac 打开 `Soda Prompt Hub.app`；Windows 打开 `Soda Compute Worker` | Mac | Windows 独立 Worker + Windows ComfyUI |

两种模式不要在同一台 Windows 上同时运行。切换模式前，应先用原启动器的“退出并停止……”入口结束上一种模式。

建议所有试验都使用单独项目，例如 `人工验收-20260914`，不要直接修改正式项目“灯蛾”。外部 API、ComfyUI 出图和模型下载可能消耗额度、显存、网络或较长时间。

## 2. WebUI 功能入口速查

打开启动器，等 Core 显示就绪后点“打开工作台”。WebUI 顶部菜单包含：

| 想做的事 | 入口 |
| --- | --- |
| 建项目、AI 补全、出图、检查结果、WD14 | `创作台` |
| 文字搜索、以图搜图、建立 CLIP 索引 | `智能检索` |
| 整理已有图片文件夹、生成双格式 Caption | `数据集` |
| 建立 LoRA 数据准备项目和交付包 | `LoRA 项目` |
| 导入单张 ComfyUI 图片、扫描结果目录 | `Windows 出图` |
| 更新提示词资料来源、重建文字索引 | `资料管理` |
| 查看设备心跳、任务、LoRA/底模清单、配置外部模型 | `设备连接` |

## 3. 配置外部 API 或本地模型服务

入口：`设备连接 → 模型接入`。

1. 选择 `LM Studio`、`OpenAI`、`Ollama` 或 `自定义`。
2. 填写显示名和 `Base URL`。需要密钥的服务再填 `API Key`。
3. 点“拉取模型”。
4. 在返回的模型中勾选要启用的模型。
5. 点“保存端点与勾选”。
6. 在页面下方“翻译与改写用哪个模型”选择模型并保存。

正常表现：拉取时有状态反馈；模型列表可选择；保存后创作台能看到所选模型。API Key 只在本机保存，页面不会重新显示明文。

如果使用 LM Studio 或 Ollama，`127.0.0.1` 指运行 WebUI 的设备：Windows 单机指 Windows，Mac 管理 Windows 时指 Mac，不会自动指向远程 Windows。

### 3.1 测试 AI 补全

入口：`创作台`。

1. 新建或打开测试项目。
2. 先写“中文创作想法”。
3. 故意留下人物、服装、动作等几个空白项；需要保留的内容可先锁定。
4. 在 `AI补全` 区选择模型。
5. 点“用所选模型补全空白项”。
6. 检查建议，确认合理后再点“确认应用”。

通过标准：按钮立即变为处理中；成功后先出现可检查的建议，不会自动覆盖锁定项；只有“确认应用”后才写入项目。失败时应显示原因，不能毫无反馈。

### 3.2 测试翻译和说明改写

有两个常用入口：

- LoRA 标签翻译：`设备连接 → LoRA → AI 翻译当前页标签`。每次只处理当前页，不修改 Windows 上的 LoRA 文件。
- Krea 2 中文翻译：`数据集 → 人工审核 → 点开一张图片 → 翻译成中文对照`。它优先翻译“视觉模型草稿”；草稿为空时翻译正式 Krea 2 英文说明。它不翻译 Anima，也不会把译文写入交付版本。同一详情页可填写修正意见，再让模型改写英文草稿。

Anima 的中文提示以 `中文（英文 canonical tag）` 标签芯片显示，是逐标签的词典或缓存对照，不是上面的 Krea 2 段落翻译框。Krea 2 翻译成功后，中文对照框会显示一整段中文，并提示导出仍使用英文草稿。

通过标准：能看到正在确认模型、处理中、完成或失败；翻译结果实际出现。不要只依据按钮颜色判断完成。

## 4. 连接 ComfyUI 并完成一次真实出图

### 4.1 Windows 单机

1. 先启动 ComfyUI，确认其网页能打开并能使用现有工作流。
2. 打开 Windows 的 `Soda Prompt Hub`。
3. 在启动器“设置”填写 ComfyUI 地址，常见值为 `http://127.0.0.1:8188`。
4. 打开 WebUI 的 `设备连接`，确认本机 Worker 在线、ComfyUI 可用。

### 4.2 Mac 管理 Windows

1. Windows 启动 ComfyUI。
2. Windows 启动独立的 `Soda Compute Worker`，不要启动 Windows 单机版。
3. Mac 启动 `Soda Prompt Hub.app`。
4. Mac WebUI 打开 `设备连接 → 设备`。
5. 首次使用时填写 Windows 主机名或局域网 IP、设备显示名和共享名，保存后点“连接 Windows”。
6. 在 macOS 系统窗口中完成 SMB 登录并选择记住密码。
7. 等待页面显示“已连接 · 可以计算”。“共享已连接”只代表目录可访问，不代表 Worker 和 ComfyUI 已经在线。

### 4.3 投递一张图片

入口：`创作台` 右侧的“生成工作流”。

1. 打开测试项目，确认 Anima 或 Krea 2 Prompt 已生成。
2. 选择“对应的 ComfyUI 工作流”。
3. 展开“模型、LoRA 与采样参数”，选择 Checkpoint、LoRA、尺寸、Sampler、Scheduler 等参数。
4. 第一次保留“先做低成本测试”，它会跳过部分精修和放大步骤。
5. 点“发送到……”。
6. 点“查看任务状态”，或进入 `设备连接 → 任务状态` 查看等待、执行、返回、完成或失败。
7. 任务返回后接收结果，回到创作台检查图片是否进入正确项目。

通过标准：Windows 实际开始出图；任务状态持续变化；结果能回到正确项目；刷新或修改项目文字后，刚导入的图片不会消失。

## 5. 更新 Windows 的 LoRA 和底模清单

入口：`设备连接`。

- LoRA：进入 `LoRA` 子页面，点“更新清单”。
- Checkpoint、UNet、VAE 等：进入 `底模` 子页面，点“更新清单”。

任务会出现在同页的“任务状态”。完成后可以按名称、路径、触发词、类型或模型系列搜索。

这里读取的是 Windows ComfyUI 中的清单和预览，不会把 `.safetensors` 权重复制到 Mac。更新需要 Windows Worker 和 ComfyUI 可用。

## 6. 安装与使用可选本地模型

入口：`设备连接 → 管理可选模型`。创作台 WD14 区也有“本地模型安装与状态”快捷入口。

| 模型 | 用途 | 约需下载 |
| --- | --- | --- |
| WD14 / `wd-swinv2-tagger-v3` | 插画、二次元 Booru 标签草稿 | 468 MB |
| `idolsankaku-swinv2-tagger-v1` | 真人、摄影标签草稿 | 420 MB |
| CLIP / `clip-vit-base-patch32` | 图片相似检索 | 352 MB |

点模型卡片的“下载并安装”，观察下载字节数、百分比、SHA-256 校验和本机推理自检。完成后应显示“可用”。可取消、续传或重试。

注意：模型安装在运行 WebUI 的设备。Windows 单机装在 Windows；Mac 管理 Windows 时装在 Mac，不会远程安装到 Windows Worker。它们也不属于 ComfyUI 的 Checkpoint 或 LoRA 目录。

### 6.1 测试 WD14

方式一，处理创作结果：

1. `创作台 → 检查生成结果`。
2. 将一张测试图“加入数据集”。
3. 打标模型选择“WD14 本地模型”。
4. 点单图的“用 WD14 生成标签”，或选择图片后点“为已选图片生成标签草稿”。
5. 人工检查标签，保存草稿或确认写入 Anima Caption。

方式二，处理已有数据集：

1. `数据集` 导入一个图片文件夹。
2. 进入步骤 `03 准备标签`。
3. 选择合适的本地 Tagger，对所选图片或整个工作区运行。

通过标准：页面显示处理进度；完成后出现可编辑的英文标签草稿；自动结果不会未经确认直接成为最终 Caption。

### 6.2 测试 CLIP 图片检索

入口：`智能检索 → 用参考图查相似图`。

1. 确认 CLIP 已安装且显示可用。
2. 点“建立 / 更新本地索引”。
3. 首次建立时观察发现文件、编码、写入索引等进度。
4. 中途点暂停或取消，再继续建立，确认已完成内容可以复用。
5. 选择一张参考图，点“查找相似图片”。

通过标准：发现文件阶段也有进度；取消能结束任务；继续后不必从零重复；搜索结果确实包含视觉相近的本地图片。图片只在本机处理。

## 7. 扫描整个 ComfyUI 结果文件夹

入口：`Windows 出图 → 扫描整个结果文件夹`。

1. 先用只含 3–5 张 PNG、JPEG 或 WebP 的小文件夹测试。
2. 填写“运行工作台的设备能访问的文件夹路径”。
3. 点“扫描这个文件夹”。
4. 确认立即出现任务文字、进度条和当前处理信息。
5. 刷新页面，确认仍能恢复当前任务状态。
6. 大目录测试时可点“取消扫描”，确认已导入图片保留、源文件不变；随后再次扫描以继续。

Windows 单机可填写本机路径，例如 `D:\ComfyUI\output`。Mac 管理 Windows 时，路径必须是 Mac 能访问的挂载路径，例如 `/Volumes/ComfyUI/output`，不能直接填 Windows 的 `D:\...`。

单次最多递归读取 2000 张。它会复制图片到资料库并制作缩略图，不移动、改名或覆盖源文件。

勾选“设为常用结果目录”后，下次进入页面会自动填入该路径；仍可随时改成另一个目录。新目录属于增补而不是覆盖：旧记录保留、相同内容按 SHA-256 跳过、同名但内容不同的图片作为新记录加入。卡片会显示手动导入、目录扫描、Worker 回传或历史导入，并记录路径和批次。

未关联项目的图片可以点“移出结果库”。该操作不删除 ComfyUI 源目录原图，Prompt Hub 的副本会进入内部回收区；已经关联项目的图片会被拒绝移出。

## 8. 更新资料库与重建本地索引

入口：`资料管理`。

1. 点检查更新，等待每个来源返回状态。
2. 对显示“可以安全更新”的单个来源点更新。
3. 更新完成后检查条目数量和状态是否刷新。
4. 需要时点“重建本地索引”。

“更新资料库”会从配置的来源获取新内容；“重建本地索引”只重新读取已经在本机的资料，不等于联网下载。网络或 Git 失败时应显示具体原因。

## 9. 数据集审核与交付

入口：`数据集`。

1. 在“导入素材”选择本地图片文件夹或上传 ZIP。
2. 依次完成 `检查问题 → 准备标签 → 人工审核 → 生成交付版本`。
3. 在人工审核中逐张点开图片，分别检查 Anima 英文标签和 Krea 2 英文自然语言。
4. 即使文字没有改动，也要点审核通过；非空草稿应同时变为已确认，空白说明不能被自动确认。
5. 运行交付前检查，通过后生成独立版本。
6. 下载 ZIP 并解压，核对图片、同名 `.txt`、`manifest.json`、`audit.json` 和 `hashes.sha256`。

通过标准：图片数与 Caption 数对应；排除的图片没有混入；两种 Caption 不互相覆盖；下载包可正常解压。

## 10. 完整个人资料备份

入口：`资料管理 → 完整备份与自动校验`。

1. 查看预计大小、目标磁盘可用空间与默认目录。
2. 留空使用默认位置，或填写一个尚不存在的新目录。
3. 点“建立完整备份”，观察复制、哈希与校验进度。
4. 完成后记录页面给出的备份目录；失败或取消不会改动原资料。

恢复仍是维护级操作，只能写入不存在或为空的新目录，不能覆盖正在使用的资料库。不要在没有命令行经验时直接恢复正式数据。

源码环境中的命令：

```bash
uv run --no-sync prompt-hub backup
uv run --no-sync prompt-hub verify-backup /绝对路径/备份目录
uv run --no-sync prompt-hub restore /绝对路径/备份目录 \
  --destination /一个不存在或为空的新目录
```

对于约 7.45 GB 的个人资料库，先准备至少 10 GB 可用空间。备份成功后要运行校验；恢复只能写入不存在或为空的新目录，不能覆盖正在使用的资料库。

备份主要覆盖 Prompt Hub 的个人数据库和受管理资料。外部数据集原图、公共来源仓库、ComfyUI 模型以及可选本地模型不应默认视为已经包含，需要另行备份。

## 11. 启动、退出和升级

### Mac

- 启动：`/Applications/Soda Prompt Hub.app`。
- 关闭窗口或点“收起窗口”：只隐藏启动台，Core 继续运行。
- 完全退出：启动台窗口或屏幕顶部菜单栏图标中点“退出并停止服务”。它不在 Dock 右键菜单中。
- 升级：先完全退出，再把新 DMG 中的 App 拖到 Applications 覆盖旧 App。个人资料不会随 App 删除。

### Windows 单机

- 启动：开始菜单中的 `Soda Prompt Hub`。
- 关闭窗口：收起到托盘。
- 完全退出：托盘菜单点“退出并停止本机服务”。
- 升级：先完全退出，再运行新的 Desktop Setup。

### Windows 独立 Worker

- 启动：开始菜单中的 `Soda Compute Worker`。
- 完全退出：托盘菜单点“退出并停止 Worker”。
- 升级：先退出旧 Worker，再运行新的 Worker Setup。

当前安装包未做 Developer ID / Windows 商业代码签名。安装前应核对 Release 文件名和 `SHA256SUMS`，不要关闭系统安全保护。验收记录应同时写明 1.1.1 安装包文件名、预发布批次和 Release 日期。

## 12. 建议由用户手动完成的高成本验收

下面这些操作依赖真实账号、模型、显卡或大量数据，适合由使用者决定何时执行：

- [ ] 外部 API 的 AI 补全成功一次，并确认额度消耗符合预期。
- [ ] 外部 API 完成一次 LoRA 标签翻译或 Krea 2 中文对照。
- [ ] Windows 单机用真实 Workflow、Checkpoint 和 LoRA 出图一次。
- [ ] Mac 管理 Windows 完成投递、Windows 出图、结果回传和导入。
- [ ] 安装 WD14，并对一张图生成、人工修改、确认标签。
- [ ] 安装 CLIP，完成全库索引、取消、继续和以图搜图。
- [ ] 扫描真实 ComfyUI 大结果目录，检查长任务进度和取消续跑。
- [ ] 对完整个人资料创建备份、校验，并恢复到全新的隔离目录。
- [ ] 从全新安装开始走一遍首次引导、安全提示、退出、重开和覆盖升级。

## 13. 验收记录模板

发现问题时，不必反复点击。记录下面的信息即可：

```text
模式：Windows 单机 / Mac 管理 Windows
安装包文件名：
Release 日期：
功能入口：例如“设备连接 → 模型接入”
操作步骤：
预期结果：
实际结果：
等待时间：
任务编号（如有）：
退出重开后是否恢复：是 / 否 / 未试
截图或日志位置：
```

截图前请遮住 API Key、Windows 账号、共享凭据和私有绝对路径。出现数据丢失、跨项目写错、进程无法退出或长时间无任何进度时，先停止该流程，再保留现场和日志。
