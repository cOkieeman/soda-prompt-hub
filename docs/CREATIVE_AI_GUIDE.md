# 场景设计、画风搭配与个人画廊

这套流程把中文想法变成可确认的画面方案，再交给现有 ComfyUI 工作流出图。AI 建议先预览；
点击采用后才修改项目。它不能保证模型一定画对，也不会自动下载模型或开始训练。

## 从想法到画面

1. 在“创作台”新建项目，写清人物、事件或情绪。已有角色、服装和画风可以填写到七个槽位并锁定。
2. 在左侧选择已接入的模型，点击“帮我设计场景”。可补充“更日常”“强调人物关系”或“保留画风但换镜头”，
   也可指定横幅、竖幅或方形；勾选保留当前宽高时，方案必须使用当前尺寸。
3. 比较 2～3 个方案：人物正在做什么、捕捉哪个瞬间、观察位置、空间安排、光源和故事线索。
   每个方案有首选尺寸及备选画幅，理由说明画面怎样变化。尺寸是构图建议，不是模型最佳分辨率或显存保证。
4. 点击“查看采用内容”，检查槽位和完整 Prompt。“补充当前项目的空白项”保留已有内容；
   “创建下一版”更新未锁定内容，并保留原项目。已锁定内容在两种方式下都受到保护。
5. 确认采用后，检查右侧 Anima 与 Krea 2 输出，再使用原有出图按钮发送任务。

完整方案 Prompt 只有在已采用方案与当前输入一致、七个槽位符合方案时才启用。
修改想法、槽位、参考、画幅或工作流控制后，旧方案会标为过期，编译回到当前项目内容；
重新设计并确认后才能启用新的完整方案。仅补空白项造成方案与已有内容不同，也会明确提示。

故事感没有固定滤镜。看向镜头、平面画风或明亮光线也能叙事；方案应具体交代动作目标、
人物与物体接触、空间关系和可见线索，避免只追加 `cinematic`、`bokeh` 等泛词。
Anima 可混合标签和自然语言，Krea 2 侧重具体连贯描述，参考
[Anima 官方说明](https://huggingface.co/circlestone-labs/Anima)与
[Krea 2 官方 prompting 指南](https://github.com/krea-ai/krea-2/blob/main/docs/prompting.md)。

## 画风与 LoRA：逐步形成自己的配方

先在“出图设置”选择目标模型族对应的 Workflow Profile，再回到“画面与提示词”，展开“画风与 LoRA 搭配建议”，填写想要的视觉效果，点击“帮我选搭配”。
建议只能选择本地清单中的真实 LoRA；模型族未知、用途缺少资料、权重未经实测都会明确标出。
工作流已有默认 LoRA 会保留；同名 LoRA 的权重覆盖和附加容量按现有工作流规则检查。

点击“查看并确认搭配”后再采用，程序会先检查当前工作流能否编译。采用只修改项目设置。
LoRA 改变后，先重新设计并确认场景，再出图。建议权重是待测试起点，不能直接视为最佳值。

做对照时固定 Seed、尺寸、Prompt 和采样设置，一次只改一个 LoRA 或权重。
用相同测试条件比较角色辨识度、动作关系、环境融合和风格偏移，在“实测备注”中写下结果，
满意后“保存为配方”。把作品放进画廊并关联项目，可同时保留文件生成信息和当时的项目快照。
项目计划与图片记录分别展示：没有生成 metadata 的图片不会凭外观猜出底模或 LoRA；
保存的节点图也不等于运行时动态节点的完整执行证明。

## 建立个人画廊

“画廊”分为“我的作品”和“收集参考”。可以搜索、收藏、填写备注与标签、加入多个图集，
记录作者和来源链接，并关联绘图项目。

可以按图片记录里的底模和 LoRA 筛选作品。详情把模型、实际使用 LoRA 的 Model/CLIP 权重、
最终正负提示词、Seed、Steps、CFG 与采样设置分开展示，支持复制提示词。
默认只展示主生成阶段的最终 Prompt；中间文本、其他阶段和原始信息收在折叠区。LoRA 优先使用 `comfyui-lora-tag-hash-metadata` 保存的 hash 与运行资源记录，未启用或零权重项不作为已使用 LoRA 展示。缺少可确认的保存记录时标为未知，不把加载列表当作使用名单。
生成尺寸与最终图片尺寸分别显示。未识别的自定义节点不会填入猜测值，完整原始 metadata 可展开核对。
这个信息组织方式参考了 [Aresmoused 作品画廊](https://aresmoused.com/works)。

支持图片内保存的 API prompt，以及已支持的 GUI workflow（含子工作流）节点记录。
你的 GUI JSON 本身能证明记录节点和连接方式；导出的图片是否包含这些字段，仍取决于
Image Saver 设置和实际输出文件。被清除 metadata 的图片只能保留“未记录”状态。

已用你提供的 Anima v2、Krea2 文生图/图生图，以及 Qwen Image 2.1 文生图/图生图/操作编辑
六份 GUI JSON 核对嵌套节点与记录字段。Qwen 操作编辑的部分 CFG 和图生图的动态 Denoise
仍显示未记录；图生图没有可确认的基础尺寸时，不使用放大后图片尺寸替代。

- 大图库：展开“添加图片与目录”，填写本机可访问的路径，选择分类，点击“登记并扫描”。
  程序只读扫描原目录，保存索引和缩略图；重复扫描跳过未改变图片，不复制整套原图。
- 少量图片：选择 PNG、JPEG 或 WebP，点击“添加图片”。选中图片作为管理副本保存到个人资料目录。
- Windows 可映射 `E:\个人开发项目\画风库` 中的具体图片目录；Mac 需要已挂载、可访问的路径，
  例如 `/Volumes/...`。另一台设备的 `E:` 路径不能直接在 Mac 使用。
- 原目录断开后仍保留缩略图、收藏、图集和备注。连接恢复后重新扫描；离线原图不能进行看图分析。
- 个人资料备份包含上传副本和缩略图，不包含映射目录的原图。原图库仍需独立备份。

## 把参考图用于创作

打开图片详情，选择项目和参考用途：画风、镜头与构图、动作与互动、光线、场景与空间或整体。
点击“加入参考”只建立引用，不直接覆盖提示词。

如需 AI 拆解，先选择支持看图的模型，点击“按参考用途分析”。图片会发送到所选模型服务。
检查实际观察和解释，点击“确认保存这次分析”后才缓存。未确认分析不进入场景或画风建议；
没有分析时只使用标题、标签和备注。原图变化后旧分析标为过期，需要重新分析并确认。

## 出图后对照方案

导入结果图后，用支持视觉的模型“对照画面方案复盘”。逐项查看原计划、实际观察、
匹配状态和改进建议。不可见的细节应标为不确定，而不是补写成事实。

“由此创建下一版”保留当前项目和结果，下一版使用建议槽位；
“补充空槽位并写入备注”保护已有和锁定内容；也可以只保存备注。
先解决一两个关键问题，再重复设计、测试和记录。

## 使用前需要准备

场景和画风建议需要已启用的文本模型；参考分析与场景复盘需要视觉模型。
在“设置 → 设备连接 → 模型接入”配置端点与模型；生成模型名称以实际服务返回为准。
外部模型建议失败时不会写入项目，也不会冒充本地分析结果。
真实绘图效果仍需要在自己的底模、LoRA、工作流与显卡上验证。

画廊图片卡片用红心收藏，点击“查看”旁的垃圾桶，确认一次即可移除 Hub 记录；详情页顶部也提供“删除图片”，包括收藏、备注与分析。源文件不会删除；目录重扫不会自动添加回来，可以手动重新添加。
